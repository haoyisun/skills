# Writing style

The reader must be able to read the material the way they read a good technical book: connected prose, clear reasoning, no filler. This contract applies to every tier.

## Banned patterns

| Pattern | Example | What to do instead |
| --- | --- | --- |
| Filler opener | "In today's fast-moving world…" | Start with the claim |
| Not-X-but-Y | "It is not a tool, it is a mindset" | Say what it is and what it does |
| Forced triads | "simple, powerful, and elegant" | Use concrete adjectives, or none |
| Dash pileups | em-dash after em-dash | Split the sentences |
| Empty transitions | "Moreover", "Furthermore", "It is worth noting" | Connect ideas with real logic |
| Restating the previous sentence | saying the same thing twice | Cut the second one |
| Bullet cliffs | a chapter made of bullets | Write prose; reserve lists for enumerations |
| Marketing register | "seamless", "revolutionary", "game-changing" | Describe behaviour |
| Vague quantifiers | "many", "most", "huge" | Give numbers or say the data is unclear |
| Explaining the obvious | "As we all know, computers use electricity" | Assume basic literacy, not domain knowledge |
| Process narration | "I carefully researched…" | Deliver the material |
| Hype in the second person | "You will be amazed" | State what the reader can do |

## Required patterns

- Connected prose: each paragraph advances one idea and links to the one before it.
- Define before use: no term before its first-use explanation.
- Cause before consequence: why it exists, what it is, how it works, when it breaks.
- Concrete examples close to the abstraction they explain.
- Numbers, versions, and names where they exist.
- Chapter-level signposts: state the question the chapter answers.
- Say "unclear" when it is unclear, instead of writing around the gap.

## Reader calibration

- Write for the lowest plausible reader in the goal card's starting point: basic reading ability, no domain vocabulary.
- Simplify the vocabulary, never the reasoning.
- Keep one idea per sentence while the reader is new to the domain; longer sentences come after the concept is established.
- When a plain-language word exists, use it first and put the term in parentheses.
- Do not pad for length. A short, complete explanation beats a long, thin one.

## Language

- Write in the goal-card language.
- Keep the original-language term in parentheses on first use when it differs from the output language.
- Do not translate idioms literally; use phrasing that a native reader of the output language would write.
- Use one term per concept for the whole material, including in examples and captions.

## The read-aloud check

Before delivering, read a random paragraph aloud as if speaking to a colleague. If it sounds like a manual, a press release, or a bot, rewrite it. If a sentence would embarrass the reader when read aloud, cut it.
